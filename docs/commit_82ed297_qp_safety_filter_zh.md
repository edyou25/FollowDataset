# 提交说明: `82ed297` QP 安全过滤与路径可视化增强

## 1. 提交概览

- 提交哈希: `82ed2970c11a1327ed4f7cefe8879bfd9e8ead52`
- 提交标题: `Implement QP-style safety filtering for 2D waypoint deltas and enhance visualizer with new path overlays`
- 提交时间: `2026-04-12 18:09:00 +0800`
- 所在分支: `feat/safe`

这次提交的目标很明确: 在不改动扩散策略主体输出方式的前提下，为机器人引入一层轻量级的局部安全过滤器，并把过滤前后的规划结果同时显示出来，便于调试和评估。

它解决的是“策略给出一串二维位移意图，但其中部分步可能在当前局部场景下不安全”这个问题。实现方式不是重新做全局规划，也不是重训策略，而是在策略输出之后增加一个 QP 风格的投影层，把 nominal 位移投影到由障碍物线性化得到的安全半空间内。

## 2. 为什么要做这次改动

在原有流程里，扩散策略负责直接输出一段未来动作或位移序列。这个方案在无障碍或障碍较少时工作正常，但存在两个明显问题:

1. 策略输出缺少显式几何安全约束。
2. 一旦在窄通道、拐角或靠近边界的位置出现障碍，系统缺少一层局部修正机制。

因此，这次提交引入的核心思想是:

- 保留扩散策略作为 nominal planner。
- 在执行前对每个二维位移做局部安全投影。
- 保持接口简单，尽量不侵入已有推理、仿真和渲染主流程。
- 提供离线评测脚本，比较启用和关闭安全层时的碰撞率。

这是一种典型的“策略负责意图，安全层负责约束”的工程拆分。

## 3. 本次提交改动了什么

本次提交一共涉及 4 个文件:

| 文件 | 作用 |
| --- | --- |
| `src/safety_filter.py` | 新增 QP 风格安全过滤器，负责把 nominal 2D delta 投影到安全可行域 |
| `planning.py` | 将安全过滤器接入主规划与执行链路，并记录安全统计与可视化路径 |
| `src/visualizer.py` | 同时显示 raw diffusion 路径和 QP 过滤后的路径 |
| `eval_safety.py` | 新增离线评估脚本，对比不同 safety mode 的碰撞与成功率 |

从工程结构看，这次提交的重点不在模型，而在“模型输出之后”的运行时安全层。

## 4. 核心设计: QP 风格安全过滤

### 4.1 输入和输出

安全过滤器的输入是单步二维位移 `ref_delta`，也就是机器人在当前时刻 nominal 想走的平面位移。

输出是:

- 一个经过修正的 `delta`
- 该步是否被修改
- 参与投影的约束数量
- 当前最小安全余量
- 调试用的候选解与选中约束信息

对应的数据结构在 `src/safety_filter.py` 中定义为:

- `SafetyConstraint`
- `SafetyProjectionResult`

### 4.2 约束来源

本次提交支持两类几何约束:

1. 圆形障碍约束
2. 线段障碍约束

圆形障碍通常用于离散障碍点或机器人/人周围的占位圆。线段障碍用于路径边界、走廊边缘或其他连续边界近似。

每个障碍都会被线性化成一个半空间约束，形式可以理解为:

```text
g^T delta <= h
```

其中:

- `g` 表示安全边界的法向方向
- `h` 表示根据当前 clearance、margin 和 alpha 计算出的允许上界

这里的本质是: 不直接求复杂的非线性避障问题，而是在当前位置附近做一阶近似，让 nominal 位移只能落在“朝安全方向收缩后的局部线性可行域”里。

### 4.3 投影策略

`src/safety_filter.py` 中的 `_project_halfspace_qp()` 实现了一个轻量化 QP 风格求解器。它没有依赖外部优化库，而是直接枚举一组低维候选解:

1. 原始参考解 `ref_delta`
2. 对单个约束做投影后的解
3. 两个约束同时激活时的交点解

然后在所有可行候选中选取与 `ref_delta` 欧式距离最小的那个。

这背后的设计取舍是:

- 维度只有 2，没必要引入重量级通用 QP 求解器
- 候选枚举更容易调试
- 可以直接把选中的约束、候选个数和解类型写入日志

换句话说，这里实现的是“QP 风格的最小改动投影”，而不是通用优化器包装。

### 4.4 关键超参数

过滤器构造时暴露了以下参数:

- `margin`: 安全边界外扩量
- `alpha`: 约束收缩强度
- `max_constraints`: 每步最多保留多少条最关键约束
- `influence_distance`: 只有距离足够近的障碍才参与约束

它们的作用分别是:

- `margin` 越大，机器人越保守。
- `alpha` 控制 nominal 位移在安全边界附近被压缩的力度。
- `max_constraints` 用于控制计算量和日志规模。
- `influence_distance` 用于避免远处障碍污染局部投影。

## 5. `planning.py` 中的接入方式

### 5.1 接入位置

这次提交把安全层接到了规划后、控制前的阶段，尤其针对 `forward_heading` 模式做了专门处理。

大致流程如下:

1. 模型输出一个未来动作序列 `action_seq`
2. 对每个 action 先转成 nominal delta
3. 调用安全过滤器生成 safe delta
4. safe delta 再映射回实际控制量
5. 执行 safe control，并把 nominal/safe 结果都缓存下来用于日志和可视化

对应主入口是 `planning.py` 中的 `_apply_forward_heading_safety_filter()`。

### 5.2 为什么对 `forward_heading` 单独处理

`forward_heading` 模式的控制输出不是直接的平面速度，而是:

- 前进幅值
- 朝向修正

因此，本次提交先通过动力学预览把 action 转成“机器人实际倾向于走出的平面位移”，然后对这个位移做安全过滤，最后再把过滤后的位移反算成控制输入。

这样做的好处是:

- 安全层操作的是清晰的二维几何量
- 与上层模型解耦
- 与下层仿真执行更一致

### 5.3 运行时缓存与统计

这次提交在 `planning.py` 里增加了几类重要状态:

- `nominal_planned_path`
- `safe_planned_path`
- `cached_nominal_delta_seq`
- `cached_safe_delta_seq`
- `cached_safety_info_seq`
- `last_safety_stats`

这些状态分别承担:

- 可视化 raw 路径
- 可视化 QP 后路径
- 记录单次推理的 nominal/safe 预测序列
- 给日志与评测脚本提供安全层统计数据

同时，推理日志里会记录:

- action 长度
- nominal action 统计
- safe delta 统计
- safety 是否修改了轨迹
- 平均偏移量
- 最小 clearance

这使得后续分析不再停留在“撞没撞”，而能定位到“安全层改了多少、从哪里开始改、是否把整段 horizon 压扁”。

## 6. 新增的可视化能力

`src/visualizer.py` 在这次提交里新增了两层路径显示:

- `Diffusion Raw`
- `QP Path`

颜色上:

- raw diffusion path 使用青色
- QP-filtered path 使用橙色

这样做的价值很直接:

1. 可以一眼看出安全层是否生效。
2. 可以判断它是在“轻微修正”还是“强行截断”。
3. 在弯道、窄通道和障碍密集区域，能快速区分问题到底来自模型还是安全层。

对于后续调试非常关键。没有这层可视化时，只看机器人实际轨迹，很难判断是模型本身没规划出来，还是安全层把 nominal 结果压掉了。

## 7. 新增的离线评估脚本 `eval_safety.py`

这次提交还补上了一个独立评估入口，用来批量比较:

- `diffusion` 模式，也就是 `safety_mode=off`
- `robot_qp` 模式

评估脚本的职责包括:

1. 生成一组共享路径样本
2. 在相同路径银行上分别运行不同 safety mode
3. 收集碰撞、成功、超时、分数和 safety 修改统计
4. 输出汇总结果到 JSON

这部分改动很重要，因为没有离线评测，安全层只能靠单个案例观察，很难判断它到底是在提高整体安全性，还是只是在个别场景下看起来更稳。

## 8. 命令行参数层面的变化

本次提交给主程序和评估脚本都补充了若干安全层参数，典型包括:

```bash
--safety-mode
--safety-margin
--safety-alpha
--safety-max-constraints
--safety-influence-distance
```

这意味着现在可以在不改代码的情况下，通过 CLI 快速做如下实验:

- 关闭安全层作为 baseline
- 只开启机器人 QP 保护
- 调整 margin 看系统保守程度
- 调整影响距离看局部约束是否过密

这对后续做参数扫描和消融实验是必要的。

## 9. 这次提交带来的直接收益

### 9.1 工程收益

- 把安全逻辑从规划主循环中抽离成独立模块
- 减少对原始策略代码的侵入
- 为日志、评估和可视化建立统一接口

### 9.2 研究收益

- 可以单独研究 safety filter 的效果，而不需要重训策略
- 可以把安全层参数作为独立实验变量
- 可以分析 nominal 规划与 safe 执行之间的偏差

### 9.3 调试收益

- 能同时看到 raw path 与 safe path
- 能量化安全层到底改了几步、改了多少
- 为后续定位“过度保守”“只截断不绕障”“卡死”等问题提供基础设施

## 10. 当前设计的边界与限制

这次提交虽然把局部安全过滤链路搭起来了，但它的能力边界也很明确:

1. 它是局部投影，不是全局重规划。
2. 它只能对 nominal delta 做最小改动，不能凭空生成强绕行动作。
3. 如果 nominal 轨迹本身太晚开始转向，局部可行域可能会迅速塌缩。
4. 当 stop 逻辑比 QP 投影更激进时，可能出现“QP 已经给出修正，但最终仍被清零”的现象。

因此，这次提交更适合作为“局部安全层”和“研究基础设施”，而不是最终形态的完整避障方案。

## 11. 适合如何使用这次提交

建议把这次提交视为一个中间层能力建设版本，适合做三类工作:

1. 基线对比: 比较 `off` 和 `robot_qp` 的碰撞率差异。
2. 可视化调试: 对照 raw path 与 QP path 判断问题来自模型还是安全层。
3. 参数消融: 研究 `margin`、`alpha`、`max_constraints` 和 `influence_distance` 的影响。

如果后续要进一步提升弯道或窄通道表现，通常需要在这个基础上继续补:

- 更合理的 stop 判据
- 原地转向恢复策略
- 多步一致性的局部重规划
- 更精细的约束筛选与优先级
